# M62 Web Client

Лёгкая замена **M Control Center** для TOPPING M62 — бекенд + веб-интерфейс.

Вместо 20 МБ Qt-приложения — небольшой Node.js-процесс, который говорит
с устройством напрямую по HID-протоколу и отдаёт API в браузер.

## Быстрый старт

```bash
npm install
npm start
# HTTP  http://127.0.0.1:8787
# WS    ws://127.0.0.1:8787/ws
```

Проверка на живом устройстве:
```bash
node src/tools/selftest.js      # CRC, кадры, открытие, 8 с прослушивания
node src/tools/catalog.js 30    # пассивная карта протокола
node src/tools/wstest.js 8787 8 # проверка WebSocket
```

## Что уже работает

**Транспорт.** HID interface 4, VID `0x152A` / PID `0x875C`. Подписка,
keepalive каждые 2 с, чтение нотификаций, кеш значений.

**Проверено на живом устройстве:**
- CRC-16/MODBUS: `CRC("123456789") = 0x4B37` — эталон совпал
- 529 чтений, 186 событий, **0 ошибок парсинга** за 8 секунд
- холостой опрос = 16 нулей (как в спецификации)

**Управление (готово к проверке записи):**
- 7 волумов с правильными диапазонами (`0..88` для микрофонов, `0..99` остальные)
- 2 селектора источников, 15 вариантов
- кривые перевода индекса в дБ

**Обнаружено сверх mainline-драйвера:** 28 тегов, из них **13 — метры уровня**,
которые драйвер игнорирует.

**Восстановлена карта EQ и микшера** (реверс кода `M Control Center`):
- 3 эквалайзера: `EQ_IN1`, `EQ_IN2` (4 полосы), `EQ_HP` (10 полос)
- микшер: 9 стерео-каналов × 8 шин (`Mix A..H`)
- всего восстановлено 223 пары «имя параметра → тег»
- каталог отдаётся по `GET /api/eq-mixer`

**Настройки устройства — сняты и проверены на живом устройстве**
(подробно: [research/PIPELINE.md](research/PIPELINE.md)):

| настройка | значения | проверено |
|---|---|---|
| Brightness | 0=Dim, 1=Normal, 2=Bright | переключением |
| Bluetooth | 0/1 | переключением |
| OTG port power | 1=Discharge, 0=Off | перебором |
| USB-C port power | 1=Charge, 2=Discharge, 3=Off | перебором |
| Auto Power On/Off | 0/1 | переключением |
| Mode select | 1=Mobile, 2=Live, 3=Pro | переключением (**перезагружает устройство**) |
| Main button single | 0=Battery, 1=Mute IN1&2, 2=Mute HP, 3=Mute OTG, 4=Toggle User, 5=Scene | переключением |
| Main button double | то же | чтением |

**Команды:** Load/Save preset 1 и 2, Scene Chat/Vocal, Reset to factory,
Load settings, Update firmware.

**Сцены разобраны полностью** (проверено диффом всего состояния):

| сцена | что делает |
|---|---|
| Chat (`0x45:0x01`) | `Ducking.DuckingSwitch = 1` — включает ducking |
| Vocal (`0x45:0x02`) | `Ducking.DuckingSwitch = 0` — выключает |

Больше **ничего** не меняют: reverb, компрессор, EQ, NC остаются как были.
Проверено повторно (Chat → Vocal → Chat) — воспроизводится.
Мануал говорит «Chat disables Reverb», но фактически это не так.

Сцену можно воспроизвести без MCC — записав `Ducking.DuckingSwitch`
в файл через `/api/workspace/apply`.

**Реверб управляется кнопками, не файлом.** Найдены 4 кнопки:

| тип | кнопка |
|---|---|
| STUDIO | `[399]` (1022,1472) |
| LIVE | `[400]` (1022,1527) |
| HALL | `[401]` (1022,1581) |
| Bypass | `[402]` (1022,1636) |

Через API: `POST /api/reverb {"type":"STUDIO"}`. **Проверены все 4 типа.**

**Пресеты частичные.** Проверено: `Save preset2` → изменить 6 параметров
в 6 блоках → `Load preset2`. Восстановились только `Input_IN1.GAIN` и
`Output_HP.GAIN`; микшер, loopback, ducking и EQ — **нет**.
Причина: пресеты хранятся в устройстве и содержат только то, что оно само
знает; микшер и EQ живут в workspace-файле на стороне Windows.

**HID-пресеты хранят только аудио-состояние.** Проверено отдельно:
`Save preset1` → изменить brightness/usbC/btnSingle → `Load preset1`:
настройки **не восстановились**. А `Save preset2` → изменить FX IN1/IN2/
NoiseRed/DryWet → `Load preset2`: **все 4 аудио-параметра вернулись**.

**Свои снимки состояния** — то, чего нет в MCC. Полного снимка «всё сразу»
вендорское приложение не умеет, поэтому бекенд собирает его сам из HID +
workspace-файла:

```
POST /api/snapshots          {label}   -> создать
GET  /api/snapshots                    -> список
GET  /api/snapshots/diff?a=&b=         -> что изменилось
POST /api/snapshots/apply    {file}    -> применить
```

Проверено: снимок содержит 38 HID-параметров + полный workspace
(микшер, EQ, входы, loopback, outputs, ducking, эффекты).
Дифф корректно определяет изменения.

**Активный workspace** надёжнее определять по реестру, не по `mtime`:
`HKCU\Software\TOPPING\TOPPING Professional Control Center\M62`
→ `M62_Live_Workspace`, `M62_Prof_Workspace`. Реализовано
`findActiveWorkspaceFromRegistry()`.

### Куда писать что — итоговая карта

| блок | файл | HID | UI |
|---|---|---|---|
| Громкости, селекторы, настройки устройства | — | **да** | да |
| Уровни FX | да | **да** | да |
| Микшер, EQ, входы, loopback, outputs, ducking | **да** | нет | да |
| **Реверб (4 типа)** | нет | нет | **да** |
| **Компрессор: Switch** | да | нет | да |
| **Компрессор: параметры** | нет | нет | **да** |

### Режим устройства меняет набор функций

| | Mobile | Live | Pro |
|---|---|---|---|
| Микшер | **нет** | 5 шин | 3 шины |
| Loopback | нет | 4 | 4 |
| Эффекты (NC, реверб) | есть | есть | **нет** |
| EQ микрофонов | нет | есть | нет |
| EQ наушников | нет | нет | **есть** |
| Ducking | есть | есть | **нет** |

Режим не читается из устройства (тег `0x11:0x1d` не возвращается) —
определяется косвенно по имени workspace и составу блоков.
Отдаётся в `GET /api/mode`, меняется через **`POST /api/mode`** —
прямым HID-кадром, **M Control Center не нужен** (проверено: все три
режима в обе стороны).

Надёжность отдельно: `node src/tools/test-robustness.js` → **20/20**

### Три канала данных — что где

| канал | что там |
|---|---|
| **HID** | громкости, селекторы, метры, джеки, настройки, FX-уровни, смена режима |
| **workspace-файл** | микшер, EQ-полосы, входы, loopback, outputs, ducking |
| **UI MCC** | реверб, компрессор-порог, sample rate/buffer, включение EQ |

**Исправлен серьёзный баг транспорта:** чтение шло по одному отчёту за
тик `setTimeout(_, 0)`, из-за чего терялось ~80% потока и приходило
2 настройки из 8 вместо всех. Теперь — пачками, **2048 чтений за 4 с
вместо 262**, и приходят все теги.

**Найдены workspace-файлы MCC** — там то, чего нет в HID
(подробно: [research/WORKSPACE.md](research/WORKSPACE.md)):

| что | где |
|---|---|
| Микшер (10 каналов × 5 шин) | `[Mixer_<CH>] Mix<BUS>_GAIN/_SOLO/_MUTE` |
| EQ (2 × 4 полосы) | `[EQ_INx] Eq%40N=\|тип\|частота\|Q\|gain\|` |
| **Фантомное питание 48V** | `[Input_INx] 48V=0/1` |
| MIC / INST | `[Input_INx] MIC=Mic1/MicHP/...` |
| Loopback (4 канала) | `[Loopback_LBxy] AudioSource/GAIN/MUTE` |
| Выходы (HP, OTG OUT) | `[Output_xxx] AudioSource/GAIN/MUTE` |
| Ducking | `[Ducking] Threshold/Attack/Reduction/Release + карта` |
| Компрессор | `[Compressor]` |

Файл обновляется по действиям в UI.

> **УТОЧНЕНО (раунд 28).** Раньше здесь было написано «MCC перезаписывает
> файл своим состоянием». **Это неверно.** Проверено: MCC файл **не трогает**
> — записал значение при работающем MCC и наблюдал 20 секунд, файл сохранил
> запись. Настоящая причина перезапуска другая: MCC держит состояние
> **в памяти** и файл обратно **не читает**. Правка файла на UI не отражается
> (проверено: в файле 11, слайдер показывает 9). Останавливать MCC нужно,
> чтобы он при **старте прочитал** файл.

**Каналы не противоречат друг другу.** Там, где параметр есть в обоих,
значения совпадают: FX-уровни 5 из 5, `Input_IN1.GAIN` в файле 43→49 и
`0x21:0x04` в HID 43→49 одновременно.

**EQ есть только в файле и только в своём режиме:**

| | режим | где |
|---|---|---|
| EQ_IN1 / EQ_IN2 (4 полосы) | Live | `[EQ_INx]` в файле |
| EQ_HP (6–10 полос) | Pro audio | `[EQ_HP]` в файле |
| через HID | — | **недоступно ни в одном режиме** |

**Запись через файл — работает.** Правка INI-файла применяется при
**перезапуске M Control Center** (не на лету, не при смене workspace).

```
POST /api/workspace/apply
{ "changes": [
    { "section": "Input_IN1",  "key": "48V",       "value": 1 },
    { "section": "Mixer_IN12", "key": "MixA_GAIN", "value": 7 }
] }
```

Сервис закрывает MCC → пишет файл → запускает MCC → перечитывает.
Цикл ~17 секунд. **Проверено на 8 параметрах: 48V, GAIN, MixA_GAIN,
MixA_MUTE, полосы EQ_IN1 ×2, полоса EQ_HP, EQ_HP.Switch — все применились.**

**Граница метода:** запись работает для параметров, **доступных в текущем
режиме устройства**. Например, `EQ_IN1.Switch` в Live-режиме MCC
сбрасывает в 0, потому что EQ входов в Live недоступен. Для EQ наушников
нужен Pro audio mode.

Валидация всех изменений идёт **до** остановки MCC, плюс авто-бэкап
`.autobak` — чтобы не оставить MCC выключенным из-за опечатки в ключе.

## Чего пока нет

| функция | почему |
|---|---|
| Полосы PEQ (тип/частота/Q) | в HID-протоколе не найдены; гипотеза — другой канал управления |
| Loopback | адреса не выяснены |
| Фантомное питание 48V | адреса не выяснены |
| Диапазоны значений EQ и микшера | адреса есть, диапазоны требуют записи в устройство |
| Декодирование метров | теги найдены, семантика не разобрана |
| **Проверка записи** | **требует разрешения — запись в устройство** |

**Важно:** всё, что делает бекенд сейчас, — **чтение**. Подписка и запрос
состояния — те же кадры, что шлёт вендорское приложение при запуске.
Фактическая запись значений на устройство **ещё не проверялась**.
Каталог EQ/микшера намеренно **не содержит функций записи**.

## Критичные уроки (для сопровождения)

Эти находки стоили времени — не повторять ошибок.

### 1. Локаль: числа из PowerShell приходят с запятой

`Write-Output $script:scale` возвращает `"1,75"`. `Number("1,75")` = **NaN**,
`SetCursorPos(NaN, NaN)` молча ничего не делает.

**Всегда:** `Number(String(out).replace(',', '.'))`.

### 2. UIAutomation может возвращать успех, не применяя значение

Для комбобоксов:
- `SelectionItem.Select()` → «SELECTED», но не меняет
- `ValuePattern.SetValue()` → «SET_OK», но не меняет
- **работает только клавиатура** (Expand → HOME → стрелки → ENTER)

**Всегда проверяйте результат чтением.**

### 3. Устройство не присылает эхо своих значений

Записали громкость — устройство молчит. Оно сообщает только о физических
изменениях (ручка, джек). Бекенд создаёт событие сам.

### 4. Смена режима требует MCC

Правильный порядок: остановить MCC → отправить `0x11:0x1d` **один раз** →
подождать → **запустить MCC** (он синхронизирует). Без MCC устройство
остаётся в промежуточном состоянии (21 тег вместо 36).

### 5. Проверять режим по HID-семействам, не по файлу

Workspace и реестр могут рассинхронизироваться. Надёжно:
- только `11,12,21-25,62,64` → Mobile
- + `0x44` → Live
- + `0x46` без `0x44` → Pro

### 6. Асинхронные операции — опрашивать, не спать

Сцена применяется за ~0.5 с, но команда может потеряться, если MCC занят.
`sleep(3000)` не гарантирует. Нужен polling до нужного значения.

### 7. Числа в inline-командах PowerShell ломаются экранированием

`node -e "..."` с `$script:`, кавычками, `\` — почти всегда ломается.
**Писать скрипт в файл**, а не inline.

### 8. Кириллица в путях и реестре

PowerShell 5.1 искажает UTF-8 в `-Command`. Передавать через временный
`.ps1` с BOM или искать файлы по списку, а не конструировать путь.

## Безопасность

- **Interface 3 (DFU) не трогается никогда** — случайная запись может
  превратить устройство в кирпич.
- Keepalive обязателен, иначе устройство замолкает.
- CRC проверяется при чтении.
- Запись в устройство выполняется **только по явной команде** и только
  в пределах известной таблицы контролов.
