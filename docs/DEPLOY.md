# Как развернуть сайт (хостинг)

> Обновлено 2026-11-19. Для владельца проекта и всех, кто хочет
> поднять свой экземпляр.

## Что вообще хостится

**Статика: один HTML-файл и 17 JS-модулей.** Всё.

Сервер **не управляет картой**. Управление идёт из браузера через
WebHID: пользователь заходит на сайт, нажимает «Подключить», браузер
спрашивает разрешение, дальше страница говорит с картой напрямую.

```
пользователь ──► сайт (статика) ──► WebHID ──► его M62
```

Данные пользователя **не покидают его компьютер**.

## Требования к сайту

| требование | почему |
|---|---|
| **HTTPS** | без него браузер не даёт `navigator.hid` (кроме localhost) |
| Chrome / Edge 89+ | Firefox и Safari WebHID не умеют |
| Десктоп | WebHID нет на Android и iOS |

Всё остальное — обычный статик-хостинг.

## Быстрый старт локально

```bash
npm install
npm start
# открой http://127.0.0.1:8080/
```

`npm start` поднимает `src/static-server.js` — минимальный сервер,
который отдаёт только сайт.

## Что внутри сервера

`src/static-server.js`, ~200 строк:

- **белый список файлов** — 17 путей, перечисленных поимённо;
- заголовки безопасности (CSP, nosniff, frame-deny);
- кэширование: HTML не кэшируется, модули на час;
- только GET и HEAD;
- обход каталога невозможен.

Серверный код (`src/server.js` с 61 маршрутом, `src/transport.js`,
`workspace.js`, `ui-control.js`) **не отдаётся** — это проверяется
тестом.

## Почему два сервера

| файл | для чего | нужен на хостинге |
|---|---|---|
| `src/static-server.js` | отдать сайт | **да** |
| `src/server.js` | агент: workspace, UIA-управление MCC, API на 61 маршрут | **нет** |

`src/server.js` — это инструмент разработки и исследований. Он тянет
`node-hid`, `ws` и Windows-специфику. На хостинге он не нужен и
вреден: увеличивает поверхность атаки.

## Варианты развёртывания

### Вариант 1: любой статик-хостинг (проще всего)

Подойдёт GitHub Pages, Cloudflare Pages, Netlify, Vercel,
обычный nginx.

Нужно отдать эти файлы по путям:

```
/                    -> web/index.html
/web/mixer-state.js  -> web/mixer-state.js
/web/scenes.js       -> web/scenes.js
/src/*.js            -> 15 модулей (список в static-server.js)
```

**Важно:** пути к модулям в `index.html` абсолютные (`/src/...`),
поэтому сайт должен лежать в корне домена, а не в подкаталоге.

### Вариант 2: свой сервер

```bash
PORT=8080 node src/static-server.js
```

Дальше — любой reverse-proxy с сертификатом (nginx, Caddy).
Caddy проще всего: сам получает HTTPS.

```
m62.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

### Вариант 3: Docker

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package.json ./
RUN npm install --omit=dev
COPY src/static-server.js src/
COPY src/*.js src/
COPY web/ web/
ENV PORT=8080
EXPOSE 8080
CMD ["node", "src/static-server.js"]
```

## Проверка перед публикацией

```bash
npm run check
```

Это линтер + офлайн-тесты + тест статик-сервера. Проверяет в том
числе, что:
- все файлы из белого списка существуют;
- серверный код не отдаётся;
- обход каталога заблокирован;
- заголовки безопасности на месте.

## Чего НЕ будет работать у пользователя

Честно говорим на странице:

| что | почему |
|---|---|
| Firefox, Safari | нет WebHID |
| Телефоны, планшеты | нет WebHID |
| `http://` кроме localhost | браузер блокирует HID |
| Чтение микшера | карта не отдаёт его по протоколу |
| Подтверждение записи в тишине | метры только при звуке |

## Безопасность: что мы гарантируем

- Сайт не отправляет данные карты на сервер — их физически нет в
  запросах.
- Нет аналитики, нет внешних скриптов (CSP это запрещает).
- Сервер отдаёт только 17 известных файлов.
- Обход каталога заблокирован (проверено тестом).
