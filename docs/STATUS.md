## Что это

Собственный клиент для аудиоинтерфейса **Topping M62** (USB `152a:875c`),
независимый от M Control Center. Состоит из:

| часть | статус | где |
|---|---|---|
| бекенд (HTTP + WebSocket) | **готов, 48 эндпоинтов** | `src/server.js` |
| документация API | **готова** | [`API.md`](API.md) |
| протокол устройства | **восстановлен** | [`PROTOCOL.md`](PROTOCOL.md) |
| факты для дизайнера | **готовы** | [`FOR-DESIGNER.md`](FOR-DESIGNER.md) |
| фронтенд | **не начат** | — |

## Главное открытие: session handshake

```
TT = 0x11, PP = 0x01, value = 1
```

**Без него устройство отдаёт 44 параметра, с ним — 96…102.**

| что раскрывается | теги |
|---|---|
| компрессор | `0x46:0x01..0x08` |
| EQ-полосы | `0x91..0x94` × `0x01..0x0a` = 40 |
| EQ-переключатели | `0x9b:0x0f/0x10/0x12/0x13` |

Открытие сделано благодаря публичной документации
[NTMan/topping-m62](https://github.com/NTMan/topping-m62). До этого
компрессор и EQ месяц считались «недоступными через HID» — это была ошибка
метода, а не свойство железа.

## Автономность от MCC — честные цифры

**Измерено по фактическим вызовам** (`node src/tools/autonomy-audit.js`,
56 пар метод+путь):

| класс | маршрутов | что значит |
|---|---|---|
| **чистый HID** | **37 из 56 (66%)** | MCC не нужен вообще, даже установленный |
| **файл MCC** | 9 из 56 (16%) | нужна установка MCC (папка Workspace), процесс — нет |
| **управляет процессом MCC** | 1 из 56 (2%) | смена режима: останавливает и запускает MCC |
| **UI MCC** | **9 из 56 (16%)** | нужен ЗАПУЩЕННЫЙ MCC |

То есть:

- **66% бекенда работает полностью автономно.**
- **82% работает без запущенного MCC**, но требует установленного.
- **16% требуют запущенного окна MCC** и падают без него.

Обновлено 2026-11-10: было 54% / 70% / 29%. EQ входов и компрессор
переведены с UIAutomation на HID — см. [`PLAN.md`](PLAN.md) и запись
`71087a5`.

### Что именно требует запущенного MCC

| эндпоинт | почему |
|---|---|
| `POST /api/reverb`, `/api/reverb/param` | карта тегов реверба не составлена, пишется через окно |
| `POST /api/eq/open`, `/api/compressor/open`, `/api/compressor/close` | открывают/закрывают окна MCC — по определению |
| `POST /api/mcc/click` | по определению клик по MCC |
| `GET /api/compressor` | **работает без MCC** (данные из HID), маркер в аудите ложный |

**EQ и компрессор больше не в списке.** Все их маршруты читают
и пишут через HID.

### Ключевое правило измерения

Устройство отдаёт блоки `0x91..0x94` (EQ входов) **только на первый
ANNOUNCE в сессии**. Проверено: 101 тег на первом, 46 на втором
в той же сессии, 97 на первом в новой.

Поэтому «снимок до / снимок после» в ОДНОЙ сессии не работает:
второй снимок всегда пуст, и это легко принять за отказ устройства.
После записи нужна НОВАЯ сессия.

### Что требует только установленного MCC (файлы)

`/api/workspace`, `/api/workspaces*`, `/api/mode` (чтение),
`/api/reverb` (чтение), `/api/eq/params`, `/api/workspace/apply`.

Путь к файлам зашит: `C:\Program Files\TOPPING Pro\M Control Center\Workspace\M62`.
**Если MCC удалить — эти 9 маршрутов перестанут работать.**
План — перейти на собственное хранилище (`src/snapshots.js`
уже умеет полный снимок), см. [`PLAN.md`](PLAN.md) §3.

## Ключевые шкалы (проверены)

```js
// Метры: dB = raw / 10, пол -90.2 dB (raw -902)
// Редукция компрессора: (comp13 - comp12) / 10
// Микшер (Q25): 0 = mute, 2^25 = 33554432 = 0 dB, +12 dB = 133582600
// EQ-полоса: 1=вкл 2=тип 3=gain дБ 4=частота Гц 5=Q*10000
// Компрессор: Ratio = значение * 10 (4.0 -> 40); 1000000 = бесконечность
```

## Чего нет и почему

| вопрос | ответ |
|---|---|
| Thesycon DSP API (микшер/EQ через IOCTL) | **тупик.** Плагина `tusbaudiodsp*.sys` нет на машине; таблицы property ID не существует («user-defined») |
| EQ / компрессор через HID | **работает.** Ранее считалось невозможным из-за ошибки метода: работающий MCC откатывал записи. См. PROTOCOL.md §5.0 |
| Прошивка | контейнер, не raw ARM. Внутри — STM32G070R (Cortex-M0+) + DSP01. Реверс не начат |
| Публичная спека от Topping | отказали 28.08.2026: «proprietary internal protocol, cannot disclose» |
| Ghidra-модули | для STM32 нужен ARM Cortex-M, Xtensa не применим |
