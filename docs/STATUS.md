## Что это

Собственный клиент для аудиоинтерфейса **Topping M62** (USB `152a:875c`),
независимый от M Control Center. Состоит из:

| часть | статус | где |
|---|---|---|
| бекенд (HTTP + WebSocket) | **готов, 48 эндпоинтов** | `src/server.js` |
| документация API | **готова** | [`API.md`](API.md) |
| протокол устройства | **восстановлен** | [`PROTOCOL.md`](PROTOCOL.md) |
| факты для дизайнера | **готовы** | [`FOR-DESIGNER.md`](FOR-DESIGNER.md) |
| фронтенд | **не начат** | — |

## Главное открытие: session handshake

```
TT = 0x11, PP = 0x01, value = 1
```

**Без него устройство отдаёт 44 параметра, с ним — 96…102.**

| что раскрывается | теги |
|---|---|
| компрессор | `0x46:0x01..0x08` |
| EQ-полосы | `0x91..0x94` × `0x01..0x0a` = 40 |
| EQ-переключатели | `0x9b:0x0f/0x10/0x12/0x13` |

Открытие сделано благодаря публичной документации
[NTMan/topping-m62](https://github.com/NTMan/topping-m62). До этого
компрессор и EQ месяц считались «недоступными через HID» — это была ошибка
метода, а не свойство железа.

## Автономность от MCC — проверено поведением

Два инструмента, и **верить надо второму**:

| инструмент | что делает | надёжность |
|---|---|---|
| `autonomy-audit.js` | смотрит вызовы функций в коде | оценка сверху |
| **`autonomy-behaviour.js`** | **дёргает маршруты, смотрит код ответа** | **факт** |

**Замер при закрытом MCC** (`node src/tools/autonomy-behaviour.js`):

```
GET-маршрутов проверено: 25
работают без MCC:        24
падает:                   1  (/api/audio-params)
```

### По классам (оценка по коду, 62 маршрута)

| класс | маршрутов | что значит |
|---|---|---|
| **чистый HID** | **53 из 62 (85%)** | MCC не нужен вообще, даже установленный |
| **файл MCC** | 7 из 62 (11%) | нужна установка MCC (папка Workspace) |
| **управляет процессом MCC** | 1 из 62 (2%) | смена режима |
| **UI MCC** | 1 из 62 (2%) | клик по MCC |

### Что действительно требует MCC

**Запущенного:**

- `POST /api/mcc/click` — по определению клик по окну MCC
- `GET`/`POST /api/audio-params` — sample rate и buffer size меняются
  только клавиатурой UIAutomation; в HID и IOCTL их нет
- `POST /api/eq/open`, `/api/compressor/open`, `/api/compressor/close` —
  открывают окна MCC (это их единственная задача)

**Установленного (файлы в `C:\Program Files\TOPPING Pro\...`):**

- `/api/workspace`, `/api/workspaces`, `/api/workspaces/*`,
  `/api/workspace/apply` — управление профилями MCC
- `/api/state/import` — импорт из MCC, по определению

**Микшер, loopback и ducking больше не зависят от этих файлов** —
они в `%APPDATA%\m62\state.json`.

### Что переведено на HID (2026-11-10)

| блок | было | стало |
|---|---|---|
| EQ входов | окно MCC, дилы клавишами | прямая запись `0x91..0x94` |
| Компрессор | окно MCC, дилы | прямая запись `0x46` |
| **Реверб** | окно MCC, дилы | **прямая запись `0x44`** |

Чтение EQ, компрессора и реверба — тоже из HID, файл не нужен.

### Две ловушки, стоившие времени

**1. EQ приходит только на первый ANNOUNCE сессии.** Повторный
announce в той же сессии блоки `0x91..0x94` не возвращает
(101 тег на первом, 46 на втором). Поэтому «снимок до / снимок
после» в одной сессии не работает — второй пуст, и это легко
принять за отказ устройства.

**2. Параметры реверба не применяются при `ReverbType = Bypass`.**
Устройство молча игнорирует запись. Это же верно для дилов в самом
MCC (NOTES §71). Из-за этого первая проверка дала ложный вывод
«реверб не пишется через HID вообще». Правильный порядок: включить
тип, потом параметры.

### Чего проверить нельзя

**Ducking и loopback** пишутся, но обратно не читаются (`IN=0`).
Подтвердить применение можно только захватом USBPcap с админом.
Проверено, что запись не ломает устройство и не сбивает другие блоки.

## Ключевые шкалы (проверены)

```js
// Метры: dB = raw / 10, пол -90.2 dB (raw -902)
// Редукция компрессора: (comp13 - comp12) / 10
// Микшер (Q25): 0 = mute, 2^25 = 33554432 = 0 dB, +12 dB = 133582600
// EQ-полоса: 1=вкл 2=тип 3=gain дБ 4=частота Гц 5=Q*10000
// Компрессор: Ratio = значение * 10 (4.0 -> 40); 1000000 = бесконечность
```

### Что осталось отреверсить (обновлено 2026-11-10, вечер)

Матрица: `node src/tools/feature-matrix.js` — **30 из 36 возможностей (83%)**.

| что | статус | почему не закрыто |
|---|---|---|
| **Sample rate / buffer** | частично | **Не протокол M62.** Это WAVEFORMATEX в реестре Windows. Читается без MCC (`samplerate-tool.ps1`), пишется через реестр + перезапуск аудиослужбы. В браузере недоступно принципиально |
| **48V запись** | нет | MCC НИКОГДА не отправляет `0x11:19` (проверено по 5 захватам USBPcap). Ни кадр, ни брекет, ни INI не работают. Нужен захват в момент нажатия кнопки — требует админа |
| **NC3** | нет | **Устройство его не поддерживает.** Код 45 отвергается, остаётся 30. У M62 только NC1 и NC2; NC3 есть в коде MCC для других моделей |
| **Маска ducking** | частично | Адреса `0x43:05/06` известны, это две маски по 8 бит (IN1 и IN2). Соответствие битов источникам не проверено — нужен захват |
| **Expander** | нет | **Не функция M62.** Строки в MCC — виджет графика (`updateChart`, `QList<QPointF>`, `CurveGreen`). Остаток общей кодовой базы |
| **`0x9b:12/13`** | частично | **Расшифровано как ENUM 0..2** (всё больше 2 схлопывается в 2). Точное назначение не установлено |

**Чего нельзя закрыть без админа:** 48V запись и биты маски ducking.
Оба требуют захвата USBPcap в момент действия в MCC.

## Чего нет и почему

| вопрос | ответ |
|---|---|
| Thesycon DSP API (микшер/EQ через IOCTL) | **тупик.** Плагина `tusbaudiodsp*.sys` нет на машине; таблицы property ID не существует («user-defined») |
| EQ / компрессор через HID | **работает.** Ранее считалось невозможным из-за ошибки метода: работающий MCC откатывал записи. См. PROTOCOL.md §5.0 |
| Прошивка | контейнер, не raw ARM. Внутри — STM32G070R (Cortex-M0+) + DSP01. Реверс не начат |
| Публичная спека от Topping | отказали 28.08.2026: «proprietary internal protocol, cannot disclose» |
| Ghidra-модули | для STM32 нужен ARM Cortex-M, Xtensa не применим |
