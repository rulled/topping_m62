# M62 — что осталось сделать руками

> Актуально на 2026-11-08, после раунда 116.

## 1. Коды источников — ЗАКРЫТО

**Все 16 кодов подтверждены на железе** одним захватом
`research/source-codes.pcap` (2 034 892 байт):

```
0x51:0x02 =  2   Mix B
0x53:0x02 =  3   Mix C
0x55:0x02 =  8   IN 1+2
0x57:0x02 = 11   OTG IN
0x64:0x02 = 14   Playback 5/6
0x62:0x02 = 15   Playback 7/8

совпало: 6, расхождений: 0
```

Вместе с ранее подтверждёнными (1, 6, 7, 9, 10, 12, 13, 16, 17) это
закрывает всё пространство кодов. **Кодов 4 и 5 не существует** — дыра;
Mix D и Mix E это шины микшера, а не источники.

INI восстановлен, устройство в исходном состоянии.

## 2. Что делать дальше (по желанию)

### 2.1 Проверить loopback в Live-режиме

Устройство сейчас в **Prof**. Loopback существует только в Live.
Тесты `0x51..0x58` в Prof показывают «нет тегов» — это ожидаемо.

Уже доказано захватами: `0x51:0x02` имеет `IN=0` во всех 6 pcap —
loopback **только пишется**, обратно не читается никогда.
См. `python src/tools/check-exact-direction.py`.

Перепроверять не обязательно.

### 2.2 Expander-блоки

В строках MCC есть `Expander_IN1`, `Expander_IN2`, но в UI и в дампах
они не встречались. Возможно, функция не реализована в прошивке.

### 2.3 Прошивка

Контейнер 1188 КБ не распакован. Внутри STM32G070R (Cortex-M0+) + DSP01.
Реверс не начат. Для STM32 нужен Ghidra с ARM Cortex-M.

### 2.4 Фронтенд

Отдельный большой этап. Бэкенд готов: 50 путей, `docs/API.md`.

| миф | реальность |
|---|---|
| «микшер не пишется» | пишется пакетом внутри `0x11:0x20`; 200/200 совпало с MCC |
| «EQ не пишется через HID» | пишется; ошибка была в коротком снимке |
| «нужен работающий MCC» | наоборот, MCC откатывает записи — его надо закрывать |
| «реверб только файлом» | читается из HID (`0x44:0x08..0x0f`) |
| «FX = 17 выдуман» | проверено вживую |
| «Mix D/E = коды 4/5» | таких кодов нет вообще |

## 5. Эндпоинты M62 — правильные

Долго искал не там. На самом деле:

```
HID interface 4 (mi_04)
  OUT 0x02   IN 0x83   — прерывания (не 0x04/0x84!)
```

`0x02` общий с bulk-аудио, различается полем transfer в заголовке
USBPcap: 3 = interrupt, 1 = bulk.
