# M62 — оценка возможности своего софта и «фишек KB22»

Итоговый документ. Только проверенные факты, с указанием метода проверки.

---

## ЧАСТЬ 1. Что уже точно установлено

### 1.1 Транспорт — общий и полностью понятный
Обе программы (M Control Center и KB Control Center):
- грузят **одну DLL** `ToppingProUsbAudioapi_x64.dll` через COM-регистрацию
  по CLSID `{E97E1508-2A66-4DF8-B7A7-32D6E5FCBA46}`;
- резолвят `TUSBAUDIO_GetDspProperty` / `TUSBAUDIO_SetDspProperty`;
- собирают **16-байтовый кадр** и кладут его в очередь по смещению `+0x48`.

Формат кадра (проверено декомпиляцией `FUN_14022ba00` в MCC и `FUN_1403702b0` в KBCC):

```
смещ.  значение
 0     0x00
 1     0x22
 2     0x33
 3     tag3  (старший байт тега)
 4..7  int32, БОЛЬШОЙ конец (big-endian)
 8     tag8
 9     tag9
10     0x00
11     0x66
12     0x00
13     0x77
```

Тег = `(tag8 << 8) | tag9`, а `tag3 == tag8` во всех разобранных случаях.

### 1.2 M62: парадокс, который надо честно назвать

**В приложении M Control Center есть код для KB22.** Проверено поиском строк:

| строка | в MCC | в KBCC |
|---|---|---|
| `DeviceKB22` | **есть** (2) | есть (4) |
| `DeviceM62` | есть (2) | **есть** (2) |
| `MainWindow_M62` | есть | — |
| `MainWindow_KB22` | **есть** (2) | есть (4) |
| `DeviceUM1` | — | есть |

То есть в обеих программах лежит код обеих моделей, а выбор идёт в рантайме
(по имени/VID:PID устройства). Это значит: **в MCC уже есть заготовки под KB22**,
но нет UI для них — потому что MCC показывает только M62.

При этом то, что **отсутствует** в MCC:

| модуль | MCC | KBCC |
|---|---|---|
| `Effect_DSP_Expand` / `Effect_DSP_Close` | **нет** | есть |
| `Compressor_FX`, `Echo_FX`, `Rever_FX`, `EQ_FX` | **нет** | есть |
| `Expander` | **нет** | есть |
| `DirectionLeft`, `DecayRate`, `GainML`, `GainMR` | **нет** | есть |
| `Mixer_IN1L`, `Mixer_IN1R` | **нет** | есть |
| `HIFI`, `Game` | **нет** | есть |

А `Effect_Compressor` — наоборот, **есть только в MCC**.

### 1.3 Прошивка M62: теги в неё не зашиты

Метод: в MCC тег компилируется как 32-битное немедленное значение.
Доказательство — реальный контекст из MCC:

```
002300db   89 45 d0  c7 45 e0 07 44 00 00  48 8b
                     ^^^^^^^^^^^^^^^^^^^^^ mov dword [rbp-0x20], 0x4407
```

Аналогично для KBCC:

```
0038059b   c0 75 0c  c7 45 e0 01 b7 00 00  e9 6e
                     ^^^^^^^^^^^^^^^^^^^^^ mov dword [rbp-0x20], 0xb701
```

**Контрольный тест** (обязателен, иначе результат недостоверен):
- `0x4401` — MCC: **25** совпадений 32-битного immediate
- `0xb701` — KBCC: **10** совпадений

**Теперь те же теги в прошивке M62 (1 216 512 байт):**

| тег | имя | MCC | KBCC | **прошивка M62** |
|---|---|---|---|---|
| 0x4401 | Input1Level | 25 | 10 | **0** |
| 0x4402 | Input2Level | 58 | 11 | **0** |
| 0x4406 | NoiseReduction | 2 | 2 | **0** |
| 0x4407 | NoiseReductionType | 1 | 1 | **0** |
| 0x4408 | DryWet | 8 | 3 | **0** |
| 0x440b | ReverbType | 2 | 2 | **0** |
| 0x440f | Width | 8 | 1 | **0** |
| 0xb701 | Ducking.Threshold | 10 | 10 | **0** |
| 0xb302 | Comp.Threshold | 14 | 11 | **0** |
| 0xc501 | Echo.PingPong | 17 | 5 | **0** |
| 0xc504 | Echo.Delay | 13 | 17 | **0** |
| 0x9b0f | EQ_FX.Switch | 7 | 2 | **0** |
| 0xab0f | EQ_HP.Switch | 1 | 3 | **0** |
| 0x3103 | Output.L.gain | 4 | 7 | **0** |
| 0x5103 | Loopback12.L | 11 | 3 | **0** |
| 0x2501 | Input1.MIX | 34 | 10 | **0** |

Проверено **77 тегов**. Единственное «совпадение» — `0x3403`, и его контекст
показывает, что это не тег:

```
0004697e   c4 e3 00 00 00 00 00 00  03 34 00 00 00 00 00 00
```

`03 34 00 00` — это не `mov dword [...], 0x3403`, а часть структуры данных.
Во всех 6 вхождениях контекст идентичен → это элемент таблицы, не код.

**Вывод: в прошивке M62 числовых идентификаторов DSP-параметров нет вообще.**
Они живут только в Windows-приложении. Прошивка принимает уже готовый кадр.

### 1.4 Формат прошивок — разные

| | M62 | KB22 |
|---|---|---|
| файл | `M62_FW87.05.45.48.27.bin` | `KB22_FW49_07_19_20_20.Topping` |
| размер | 1 216 512 | 4 313 088 |
| магия | нет (таблица подобразов) | `ZDPTTTTTI` (6 раз) |
| энтропия | 0.7–7.8, **открытый код** | 8.00 в диапазонах 0x0–0x60000 и 0x330000–0x410000 |
| архитектура | не x86 (нет `83 EC`, `55 89 E5`) | ARM (Keil, `ER_IROM1`) |
| загрузчик | — | открыт в 0x410000+, IAP + FAT |

Заголовок M62 содержит таблицу подобразов:
```
@0x40: offset=0x00f18a size=0x05797 tag=0x08200020
@0x60: offset=0x105fc8 size=0x0c171 tag=0x08300020
```
Адрес `0x20568E` (встречается дважды) лежит за пределами файла → это адрес
загрузки, не смещение.

## ЧАСТЬ 2. ОТВЕТ НА ВОПРОС

### 2.1 Свой лёгкий софт под M62 — ДА, полностью реально

**Обоснование.** Всё, что нужно, установлено фактами:
1. API-поверхность известна: 83 экспорта `ToppingProUsbAudioapi_x64.dll`, из них
   для DSP нужны два — `GetDspProperty` и `SetDspProperty`.
2. Формат кадра известен до байта (§1.1).
3. Теги M62 известны из MCC (§1.3, 13 параметров `0x4401..0x440f`).
4. Загрузка DLL — через реестр, задокументированный CLSID.
5. Прошивка M62 не зашифрована, значит при необходимости её тоже можно читать.

Объём: пара сотен строк C++ вместо 20 МБ Qt. Работает без прошивки, без патчей.

**Ограничение, которое надо принять:** свой софт сможет управлять только теми
13 параметрами, что понимает прошивка M62 (§1.3).

### 2.2 Фишки KB22 в M62 — ОЦЕНКА: маловероятно, но есть один шанс

**Аргументы ПРОТИВ (сильные):**
- В прошивке M62 **нет ни одного** идентификатора тега (§1.3). Проверено 77 тегов,
  контрольный тест пройден.
- Модули `Effect_DSP_Expand`, `Compressor_FX`, `Echo_FX`, `Rever_FX`, `EQ_FX`,
  `Expander`, `Crossfeed` в MCC **отсутствуют как код**.
- Прошивки под разные архитектуры и разного размера (1.2 МБ против 4.3 МБ).

Если бы прошивка M62 умела Ducking/Echo/Expander, разработчику не нужно было бы
писать отдельный `Effect_DSP_Expand` только для KB22 — он бы переиспользовал
существующий код.

**Аргумент ЗА (один, но реальный):**
В MCC присутствуют `DeviceKB22` и `MainWindow_KB22`. Это значит, что
**Windows-часть M Control Center уже содержит транспортный код KB22**. Тот факт,
что теги не найдены в прошивке M62, не исключает, что прошивка обрабатывает
**другие** номера (прошивка — чёрный ящик, у нас нет её дизассемблера).

**Что нужно, чтобы закрыть вопрос окончательно (по возрастанию риска):**

1. **Бесплатно и безопасно:** разобрать прошивку M62 в Ghidra. Архитектура пока
   не определена (не x86, не ARM32/ARM64, не MIPS в чистом виде). Определить её —
   и найти обработчик кадра. Это даст точный ответ без единого байта записи.
2. **Требует согласия:** отправить один кадр с тегом KB22 (например `0xb701`)
   через `TUSBAUDIO_SetDspProperty` и посмотреть код возврата. Это **запись
   в устройство** — я этого без твоего разрешения не делаю.

### 2.3 «Тот же процессор» — НЕ подтверждается

Твоя гипотеза не выдержала проверки:
- M62-прошивка не x86 (нет ни одного `83 EC`, `55 89 E5`, `8B 44 24`);
- KB22-прошивка — ARM (Keil MDK, `ER_IROM1`), зашифрована;
- размеры 1.2 МБ против 4.3 МБ.

Это **разные чипы**. Общий у них — только протокол обмена (16-байтовый кадр)
и Windows-драйвер.

### 2.4 Каскадный фильтр (Biquad)

`Biquad` встречается **только в KBCC** (MCC: 0).

## ЧАСТЬ 3. Что делать дальше

**Приоритет 1 — бесплатно, без риска:**
Определить архитектуру прошивки M62 и разобрать её в Ghidra. Если найдётся
обработчик кадра — получим окончательный ответ про фишки KB22, не трогая железо.

**Приоритет 2 — если приоритет 1 не даст ответа:**
Написать read-only пробник: открыть устройство, вызвать `TUSBAUDIO_GetDspProperty`
для тега KB22. Только чтение, ничего не меняется.

**Приоритет 3 — требует явного разрешения:**
Один тестовый `SetDspProperty` с чужим тегом.

**Параллельно:** писать свой лёгкий клиент под 13 подтверждённых параметров M62 —
это гарантированно работающий результат, независимо от исхода по фишкам KB22.
