# РЕВЕРС ПРОШИВКИ M62: архитектура найдена

> Дата: 2026-11-19. **Статус: разблокировано.**
> Предыдущий вывод «Ghidra напрямую не поможет» — **ОПРОВЕРГНУТ**.

## Короткий итог

Прошивка M62 — это **настоящий код XMOS xCORE (XS3)**, и он
**разбирается** в Ghidra с модулем из issue #5835.

| что | результат |
|---|---|
| Архитектура | **xCore XS3** (не ARM, не x86) |
| Чип | **XMOS XU316-1024-QF60** (по корпусу DSP01) |
| Дизассемблер | Ghidra 12.1.4 + модуль `CUB3D/ghidra` (ветка `xmos_proc`) |
| Язык в Ghidra | **`XCORE:LE:32:default`** |
| Код читается | **ДА**, проверено метрикой и глазами |

## Как это установлено (четыре независимых свидетельства)

### 0. Разборка карты (прямое указание)

На ASR один из владельцев разобрал свой M62 и перечислил компоненты
(пост #37 ветки `topping-m62-thread.67739`). Среди них:

    1x Topping DSP01 — этот чип

Он же указал остальные: 2x ESS ES9821Q (АЦП), AKM AK7604
(аудио-процессор), STM32G070R (контроллер). Полный список —
`research/HARDWARE.md`.

То есть **наличие DSP01 подтверждено независимо**, а не по фото.


### 1. Корпус чипа

На фото платы чип с маркировкой `TOPPING Professional DSP01` в
корпусе **QFN, 60 выводов, 7×7 мм**. Это точное совпадение с
**XMOS XU316-1024-QF60A/B** — единственным вариантом XU316 в таком
корпусе.

См. `research/BOARD-PHOTOS.md`.

### 2. Профиль инструкций совпадает с эталоном

Скачан **эталонный образ XU316** из открытого проекта
(`ffva_v1.3.1_factory.bin`, собран штатным `xflash`). Сравнение
профилей мнемоник, 60 000 инструкций:

| файл | уникальных | **доля топ-10** |
|---|---|---|
| эталон XU316 | 127 | **58,9%** |
| **наш M62** | 120 | **55,5%** |
| случайный шум | 171 | **30,6%** |

**Ключ — концентрация.** У кода топ-10 инструкций занимают больше
половины; у шума — треть. Наш образ концентрирован как код.

Косинус: наш↔эталон **0,8497**, наш↔шум 0,6220, эталон↔шум 0,5742.

### 3. Дизассемблер выдаёт осмысленный код

Участок 0x101000:

```
ld16s r5,r10,r8
brft  r7,0x101082     <- переход на вычисленный адрес
subi  r6,r2,0xc
brft  r3,0x101024
clz   r0,r4
lss   r4,r4,r9
ld16s r6,r10,r8
brft  r7,0x10108e
```

Регулярный цикл с корректными нарастающими адресами (0x082, 0x08e,
0x09a...) — так выглядит настоящая обработка массива.

## Структура образа

```
0x000000..0x027000  подобраз 1  (магия 0xc07aaf11 в начале)
0x027000..0x08f000  подобраз 2
0x08f000..0x0fc000  подобраз 3
0x0fc000..0x129000  подобраз 4
```

Повторяющиеся ряды нулей по 2724 и 1375 байт — в каждом подобразе
одинаковые, то есть это таблицы/выравнивание, а не копии.

**Плотный код** сосредоточен в районах: 0x096800, 0x097800, 0x0ff800,
0x101000 (~99,9% ненулевых байт).

## Что даёт позитивная проверка

Модуль проверен на **положительном контроле** (эталон XU316 —
работает) и **отрицательном** (случайный шум — профиль плоский,
концентрация 30,6%). Только после этого вывод про нашу прошивку
имеет вес.

Это важно, потому что три предыдущие метрики по прошивке давали
ложный результат (см. `research/FIRMWARE-CONCLUSION.md`).

## Что осталось

1. **Найти точки входа.** В образе нет явного ELF-заголовка, поэтому
   надо определить, откуда начинается исполнение (вероятно, из
   заголовка `0xc07aaf11`).
2. **Разметить функции.** Модуль CUB3D неполный — автоанализ Ghidra
   может спотыкаться. Нужны ручные проходы.
3. **Разобрать таблицы данных.** Параметры DSP (коэффициенты
   фильтров, таблицы эффектов) лежат между блоками кода.
4. **Понять контейнер `0xc07aaf11`.** Уже известно: это НЕ шифрование
   (код читается). Скорее заголовок разделов.

## Как повторить

```bash
# 1. установить модуль (один раз)
#    https://github.com/CUB3D/ghidra/tree/xmos_proc/Ghidra/Processors/xmos
#    -> <ghidra>/Ghidra/Processors/xmos/

# 2. импорт с правильным языком
analyzeHeadless <proj> M62XS3 -import <файл> \
  -processor "XCORE:LE:32:default" -noanalysis

# 3. профиль мнемоник
analyzeHeadless <proj> M62XS3 -process <файл> -noanalysis \
  -scriptPath research/ghidra-scripts -postScript MnemonicProfile.java

# 4. дизассемблер
analyzeHeadless <proj> M62XS3 -process <файл> -noanalysis \
  -scriptPath research/ghidra-scripts -postScript ShowDisasm.java 0x101000 45

# 5. сравнение профилей с эталоном и шумом
python src/tools/compare-mnemonic-profiles.py
```

## Осторожно: что НЕ доказано

- Что `DSP01` — именно XU316, а не другой чип того же корпуса.
  Корпус совпадает, но маркировка перекрыта логотипом Topping.
- Что контейнер `0xc07aaf11` — заголовок разделов, а не сжатие.
  Код читается напрямую, но не факт, что целиком.
- Что все четыре подобраза — код. Часть может быть данными.
