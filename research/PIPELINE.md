# ПОЛНЫЙ ПАЙПЛАЙН M CONTROL CENTER — карта для бекенда

Дата: 2026-11-07. Метод: реверс `M Control Center.exe` (capstone) +
проверка на живом устройстве (UIA Invoke + чтение HID).

**В устройство напрямую я не писал.** Писал MCC через UI Automation,
слушал HID. Это разрешённый режим.

---

## 0. КРИТИЧЕСКАЯ НАХОДКА ПРО DPI

На этой машине **DPI = 168, масштаб 1.75**.
UI Automation возвращает координаты в **логических** пикселях,
а `SetCursorPos`/`SendInput` работают в **физических**.

**Все клики мышью до этого били мимо на 75%.** Именно поэтому:
- перетаскивание dial'ов «двигало окно», а не регулятор;
- правый клик по панели FX ничего не открывал.

Решение: клики делать через `UIA Invoke/Toggle` (они DPI-независимы),
а координаты для мыши делить на 1.75.
Инструмент: `src/tools/uia.js` (экспортирует `scale`, `dumpTree`, `invoke`).

### СБРОС К ЗАВОДСКИМ (0x11:0x21) — ПРОВЕРЕНО

**Команда `0x11:0x21 = 1`. ДЕСТРУКТИВНА.**

**Что происходит:**
1. Кадр отправлен — устройство **немедленно перезагружается**
   (HID отваливается с ошибкой чтения).
2. Через ~8 секунд HID возвращается, но на ANNOUNCE **не отвечает**
   (0 параметров) — нужно запустить MCC, чтобы устройство ожило.
3. После запуска MCC отдаёт состояние.

**Что сбрасывается:**

| параметр | было | стало |
|---|---|---|
| `0x1104` Brightness | 0 (Dim) | 1 (Normal) |
| `0x111b` OtgPower | 0 (Off) | 1 (Discharge) |
| `0x111e` AutoPower | 1 (On) | 0 (Off) |
| `0x1122` MainButtonSingle | 2 | **0 (Battery Level)** |
| `0x1123` MainButtonDouble | 4 | **1 (Mute IN1&2)** |
| `0x4406` NoiseReduction | 35 | 15 |
| `0x4407` NC type | 15 | 0 (Bypass) |

**Что НЕ сбрасывается — workspace-файл:**

| параметр в файле | после сброса |
|---|---|
| `Input_IN1.GAIN` | без изменений |
| `Mixer_IN12.MixA_GAIN` | без изменений |
| `EQ_IN1.Eq%401` | без изменений |
| `ReverbType` | без изменений |
| `Loopback_LB12.GAIN` | без изменений |
| `Output_HP.GAIN` | без изменений |

**Вывод: `RestoreDefault` сбрасывает только внутреннее состояние устройства,
но НЕ трогает workspace-файл.** После сброса нужно отдельно сбросить
и файл (взять заводской из бэкапа или создать новый workspace).

**Восстановление после сброса:** настройки пишутся обратно через HID
(`0x11:0x04`, `0x11:0x1b`, `0x11:0x1c`, `0x11:0x1e`, `0x11:0x22`,
`0x11:0x23`, `0x44:0x06`, `0x44:0x07`). Проверено — все принимаются.

**Осторожно:** сразу после сброса устройство может не принять часть
значений (нужно подождать и повторить). Проверено: `0x44:0x06 = 35`
не принялось с первого раза, со второго — принялось.

## 2. СЦЕНЫ (TT=0x45) — РАЗОБРАНЫ ПОЛНОСТЬЮ

| тег | имя | поведение |
|---|---|---|
| `0x45:0x01` | **Chat** | команда, обратно НЕ читается |
| `0x45:0x02` | **Vocal** | команда, обратно НЕ читается |

### 2.1 Проверка: сцены меняют РОВНО ОДИН параметр

Метод: диф **всего INI-файла** и всех HID-тегов до/после нажатия.

| сцена | изменение в файле | изменение в HID |
|---|---|---|
| **Chat** | `Ducking.DuckingSwitch: 0 → 1` | `0x43:0x07: 0 → 1` |
| **Vocal** | `Ducking.DuckingSwitch: 1 → 0` | `0x43:0x07: 1 → 0` |

Проверено повторно (Chat → Vocal → Chat) — воспроизводится стабильно.

### 2.2 Что сцена НЕ меняет (проверено)

| параметр | после сцены |
|---|---|
| `Effect_Integration.ReverbType` | остаётся `Bypass` |
| `Effect_Integration.MuteFX` | остаётся `false` |
| `Effect_Integration.NoiseReductionType` | остаётся `NC1` |
| `Compressor.Switch` | остаётся `true` |
| `EQ_IN1.Switch` | остаётся `0` |

### 2.3 Расхождение с мануалом

Мануал M62 говорит:
> «Chat Scene: Enables Ducking and disables Reverb.»
> «Note: Scene presets only change the on/off state of Ducking and Reverb.»

**Фактически сцена меняет ТОЛЬКО Ducking.** Reverb не трогает — остаётся
тем, чем был (в тесте — `Bypass`, то есть уже выключен).

Возможно, мануал описывает намерение, а реализация упрощена. Проверка
с принудительно включённым ревербом не удалась: `ReverbType=Studio`,
записанный в файл, MCC вернул в `Bypass` — значит реверб включается
не через этот ключ, и вопрос остаётся открытым.

### 2.4 Вывод для бекенда

Сцена — это **макрос из одного действия**: включить (Chat) или выключить
(Vocal) ducking. Ничего больше не происходит.

Если нужно повторить поведение сцены без MCC — достаточно записать
`Ducking.DuckingSwitch` в файл.

### 3.4 Практический итог для бекенда

| что нужно сохранить | куда |
|---|---|
| аудио-состояние (FX, эффекты) | `Save preset` в устройстве |
| микшер, EQ, loopback | workspace-файл |
| настройки устройства | **нигде** — пресет их не хранит |

**Полного снимка «всё сразу» в MCC нет.** Для бекенда правильнее делать
свой снимок: собрать состояние из HID + файла и сохранить как JSON.

## 9. ЧТО ПРОВЕРЕНО НА ЖИВОМ УСТРОЙСТВЕ (раунд 1)

### 9.0 ГЛАВНОЕ: НАЙДЕН БАГ В ТРАНСПОРТЕ — ОН ТЕРЯЛ 80% ПОТОКА

**Симптом:** сервер отдавал 2 настройки из 8, при этом отдельный скрипт
на том же устройстве — все 8.

**Причина:** старый `#startReading()` делал **одно** чтение за тик:

```js
data = this.device.readTimeout(200);
if (data && data.length) this.#handleReport(data);
this.readTimer = setTimeout(tick, 0);   // <- ~65 тиков/сек
```

`setTimeout(_, 0)` в Node даёт примерно **65 итераций в секунду**.
Устройство шлёт сотни отчётов в секунду. Значит ~80% отчётов
**физически не прочитывались** — они оставались в буфере и перезаписывались
новыми, а состояние, пришедшее «порциями», до кеша не доходило.

**Замеры (одно и то же устройство, 4 секунды):**

| реализация | чтений | параметров в кеше | настроек TT=0x11 |
|---|---|---|---|
| было: 1 чтение за `setTimeout(…, 0)` | **262** | 26 | **2 / 8** |
| стало: пачка до 64 чтений за тик | **2048** | 51 | **8 / 8** |

**Исправление** (`src/transport.js`, метод `#startReading`): внутри одного
тика вычитываем пачку отчётов, пока они идут, и только потом отдаём
управление event loop. Короткий таймаут `readTimeout(5)` вместо `200` —
чтобы пачка завершалась сразу, когда данных нет.

**Это была самая серьёзная ошибка в бекенде.** Она не выглядела как ошибка:
не было исключений, `parseErrors` = 0, кеш пополнялся. Просто тихо
терялась большая часть состояния устройства — и ровно те теги, которые
приходят «редкими порциями» (настройки).

**Brightness** (`0x11:0x04`), комбобокс:
| пункт UI | значение |
|---|---|
| Dim | **0** |
| Normal | **1** |
| Bright | **2** |

### 9.3 Варианты Main button — ПОЛНЫЙ СПИСОК (из бинарника)

Строки лежат подряд в `.rdata`, индексация **с 1**:

| значение | действие | адрес строки |
|---|---|---|
| 0 | Battery Level | 0x28a9e8 |
| **1** | Mute IN1&2 | 0x28a9f8 |
| **2** | Mute HP Out | 0x28aa08 |
| **3** | Mute OTG Out | 0x28aa18 |
| **4** | Toggle User 1/2 | 0x28aa28 |
| **5** | Chat/Vocal scene | 0x28aa38 |

**Подтверждено:** `MainButtonSingle = 1` (Mute IN1&2) — совпадает с UI.
После переключения на «Mute HP Out» стало **2** — совпадает.

`MainButtonDouble = 4` = «Toggle User 1/2» — совпадает с UI.

### 9.4 Прочие варианты (из бинарника)

**Brightness** (`.rdata` 0x272b2c): `Dim`=0, `Normal`=1, `Bright`=2
— **подтверждено живьём**.

**UsbCCharging**: `Charge`=1, `Discharge`=2, `Disabled`=3
— подтверждено чтением (=1 Charge).

**Mode select**: `Mobile mode`=1, `Live streaming mode`=2, `Pro audio mode`=3
— **порядок подтверждён** переключением (Pro дал 3 шины, Live — 5).

### 9.5 ЧЕГО УСТРОЙСТВО НЕ ВОЗВРАЩАЕТ

| тег | факт |
|---|---|
| `0x11:0x1d` (Mode) | **никогда не приходит**, ни до, ни после смены режима |
| `0x11:0x21` (RestoreDefault) | команда, не состояние |
| `0x11:0x1f` (UpdateFirmware) | команда |
| `0x11:0x20` (LoadSettings) | команда |
| `0x45:0x01/0x02` (Scenes) | команда, не состояние |

**Как определять режим без `0x11:0x1d`** — по косвенным признакам
(реализовано в `src/tools/detect-mode.js`):

| признак | Live | Pro | Mobile |
|---|---|---|---|
| шин микшера в UI | 5 | 3 | 0 |
| эффекты `0x44`: читаются | да | да | ? |
| EQ наушников `0xab` | нет | да | нет |

### 9.6 Критично: смена режима = перезагрузка

При переключении режима устройство **пропадает из USB на 1-8 секунд**.
Приложение обязано это переживать: переподключиться, заново подписаться,
перечитать состояние.

**Проверено:** после смены режима HID вернулся, устройство ответило на
ANNOUNCE, набор тегов изменился (51 параметр в Live, 26-63 переходных).

## 10. ЧТО ЕЩЁ НЕ СНЯТО

| функция | статус |
|---|---|
| Смена режима (Mobile/Live/Pro) | тег `0x11:0x1d` есть, значение не приходит — нужна проверка сменой режима на устройстве |
| Bluetooth вкл/выкл | `0x11:0x1a` читается (=0), команда не проверена |
| Brightness смена | `0x11:0x04` читается, смена не проверена |
| AutoPoweroff значения | `0x11:0x1e` = 0, что значит — неясно |
| MainButtonSingle/Double | `0x11:0x22`=1, `0x11:0x23`=4 — что за значения, неясно |
| Микшер | не HID (доказано перебором) |
| Loopback | тег не найден |
| 48V фантом | тег не найден |
