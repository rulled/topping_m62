# МЕТОД ЗАПИСИ ЧЕРЕЗ WORKSPACE-ФАЙЛ — РАБОТАЕТ

Дата: 2026-11-07, раунд 5.

**Главное открытие:** правка workspace-файла **применяется**, но только
при **ЗАПУСКЕ M Control Center**. Не при переключении workspace, не на лету.

---

## 1. Проверенный эксперимент

### Что делали

1. Закрыли MCC полностью (`Stop-Process -Force`).
2. Записали в активный файл `M62_Live_ввв.ini` заведомо чужие значения:
   - `Input_IN1.GAIN = 11` (было 49)
   - `Mixer_IN12.MixA_GAIN = 5` (было 12)
   - `Mixer_IN12.MixA_MUTE = true`
3. Запустили MCC заново.
4. Посмотрели: что в файле и что в UI.

### Результат

| проверка | результат |
|---|---|
| файл после запуска | `GAIN=11`, `MixA_GAIN=5`, `MixA_MUTE=true` — **мои значения сохранены** |
| слайдер Mix A в UI (idx 146) | **val = 5** — совпадает с записанным |
| MCC вернул свои? | **нет** |

**Вывод: правка файла при старте MCC ПРИМЕНЯЕТСЯ.**

---

## 2. Разница с предыдущими тестами

| способ | результат |
|---|---|
| правка активного файла при работающем MCC | **не применяется** — MCC держит состояние в памяти и перезаписывает файл |
| правка файла + переключение workspace | **частично** — файл читается, но не все поля |
| правка файла + **ПЕРЕЗАПУСК MCC** | **ПРИМЕНЯЕТСЯ** ✅ |

То есть предыдущий вывод «файл — приёмник, а не источник» был **неполным**.
Он верен только для работающего MCC. При старте файл — источник.

## 3. КАК ЗАПИСЫВАТЬ (рабочий рецепт)

```js
import { execFileSync } from 'node:child_process';
import { findActiveWorkspace, readWorkspace, writeWorkspace } from './src/workspace.js';

const sleep = (ms) => new Promise(r => setTimeout(r, ms));
const MCC = 'C:\\Program Files\\TOPPING Pro\\M Control Center\\M Control Center.exe';

// 1. закрыть MCC
execFileSync('powershell.exe', ['-NoProfile', '-Command',
  'Stop-Process -Name "M Control Center" -Force -ErrorAction SilentlyContinue']);
await sleep(4000);

// 2. прочитать активный файл
const ws = findActiveWorkspace();
const ini = readWorkspace(ws.path);

// 3. изменить нужные ключи
ini.Mixer_IN12.MixA_GAIN = '5';
ini.Input_IN1.GAIN = '11';

// 4. записать
writeWorkspace(ws.path, ini);

// 5. запустить MCC
execFileSync('powershell.exe', ['-NoProfile', '-Command', `Start-Process "${MCC}"`]);
await sleep(13000);
```

**Важно:**
- закрывать именно `Stop-Process -Force` (обычное закрытие окна не всегда работает);
- ждать ~4 с после закрытия, ~13 с после запуска;
- **не менять файл при работающем MCC** — он перезапишет.

## 4. ЧТО ЭТО ОТКРЫВАЕТ

## 5. ОГРАНИЧЕНИЯ

1. **Требуется перезапуск MCC** — 13+ секунд на цикл. Для интерактивного
   веб-клиента это неприемлемо; нужно чередовать с UI-автоматизацией.
   > **УТОЧНЕНО (§60):** причина не в том, что MCC перезаписывает файл
   > (он его **не трогает**), а в том, что MCC держит состояние
   > **в памяти** и файл обратно **не читает**. Перезапуск нужен,
   > чтобы MCC прочитал файл при старте.
2. **MCC должен быть установлен.** Если его нет — метод не работает.
3. **Формат недокументирован** — всё восстановлено наблюдением.
4. **Не все ключи проверены.** Проверены: `MixA_GAIN`, `Input_IN1.GAIN`,
   EQ-полосы, ducking, loopback, outputs, compressor.Switch.
   Остальные (~790) — по аналогии, но не поштучно.
   Аудит покрытия (§52): 793 ключа, парсер покрывает все, кроме
   6 флагов-идентификаторов секций.
5. **`0x21:0x04` в HID не всегда приходит** — устройство отдаёт его
   не в каждом ANNOUNCE. Не пугаться, если в HID пусто.
6. ~~Файл может быть перезаписан MCC при выходе~~
   > **ОПРОВЕРГНУТО (§60):** MCC файл **не перезаписывает** —
   > проверено наблюдением 20 секунд при работающем MCC.
   > Бэкап всё равно делать при закрытом MCC — ради консистентности,
   > но риск потери невелик.
7. **«Load settings» (`0x11:0x20`) не помогает** — проверено, MCC
   по этой команде файл не перечитывает. Для применения правок
   нужен именно перезапуск.

## 6. АЛЬТЕРНАТИВА: без перезапуска

Если перезапуск недопустим, писать через **UI Automation**:

| действие | метод |
|---|---|
| микшерный фейдер | `RangeValuePattern.SetValue()` — **работает** |
| GAIN входа | перетаскивание dial (DPI-коррекция 1.75) |
| кнопки 48V/MUTE/MIC | `InvokePattern` |
| селекторы (AudioSource) | клавиатура (Home + Down × N + Enter) |
| EQ-полосы | диалог EQ (не разобран) |

Оба пути дают один результат — проверено: `MixA_GAIN` из файла = 5
и в UI = 5.

## 7. ГРАНИЦА: ЧТО ПИШЕТСЯ, А ЧТО НЕТ (проверено записью)

Полный прогон через `POST /api/workspace/apply`.

### 7.1 ПИШЕТСЯ (подтверждено)

| параметр | было → стало | проверка |
|---|---|---|
| `Input_IN1.48V` | 1 → 0 | OK |
| `Input_IN1.GAIN` | 33 → 20 | OK |
| `Mixer_IN12.MixA_GAIN` | 5 → 7 | OK |
| `Mixer_IN12.MixA_MUTE` | true → false | OK |
| `EQ_IN1.Eq%401` (полоса) | gain 0 → 6 | OK |
| `EQ_IN1.Eq%402` | gain 0 → −4 | OK |
| **`EQ_HP.Eq%401`** (в Pro) | gain 9 → 5 | **OK** |
| **`EQ_HP.Switch`** (в Pro) | true | **сохранился** |

### 7.2 НЕ ПИШЕТСЯ

| параметр | что происходит |
|---|---|
| `EQ_IN1.Switch` в **Live** | MCC сбрасывает в `0` |

**Причина:** в Live streaming mode EQ_IN1/EQ_IN2 **недоступны** —
ни в UI, ни в HID (см. CROSSCHECK.md §7.1). MCC игнорирует и сбрасывает
флаг блока, недоступного в текущем режиме.

**Проверял формат:** `1` и `true` — оба сбрасываются.

### 7.3 ГЛАВНЫЙ ВЫВОД

> **Запись через файл работает для параметров, доступных
> в текущем режиме устройства.** Недоступные блоки MCC игнорирует.

Это НЕ баг метода, а логика устройства: режим определяет, какие блоки есть.

### 7.4 Следствие: для EQ наушников нужен Pro-режим

| что нужно | режим |
|---|---|
| EQ_IN1 / EQ_IN2 (4 полосы) | Live streaming |
| EQ_HP (6–10 полос) | Pro audio |
| Микшер A–E (5 шин) | Live streaming |
| Микшер A–C (3 шины) | Pro audio |

Переключение режима **перезагружает устройство** (1–8 с) и меняет
активный workspace-файл.

## 8. ПРОВЕРЕННЫЙ ФОРМАТ EQ-ПОЛОС

### 8.1 EQ_IN1 / EQ_IN2 (формат `in`)

```
|тип|частота|Q|gain|
```
Запись `|0|632|0.7|6` → полоса с gain = 6 дБ на 632 Гц, Q 0.7. **Работает.**

### 8.2 EQ_HP (формат `hp`, порядок другой!)

```
тип|gain|частота|Q|флаг
```
Запись `0|5|35|0.5395|1` → полоса с gain = 5 дБ на 35 Гц, Q 0.5395. **Работает.**

**Легко ошибиться:** позиции gain и частоты в двух форматах поменяны местами.

## 10. КОМПРЕССОР: ОСОБЫЙ СЛУЧАЙ

Компрессор **не пишется через файл** и **не принимается через HID**.
Это единственный блок с такой особенностью.

### 10.1 Что проверено

| способ | результат |
|---|---|
| файл: `Compressor.Threshold = -12` + перезапуск | **не применилось** (осталось −18) |
| файл: `Compressor.Ratio = 6` | **не применилось** (осталось 4) |
| файл: `Compressor.Switch = true` | **применилось** (сохранилось) |
| HID: `0x46:0x02 = -12` | **устройство не приняло**, теги не приходят |
| **UI: перетаскивание dial Threshold** | **РАБОТАЕТ** (−18 → −26) |

### 10.2 Вывод

`Switch` компрессора пишется через файл, а его **параметры
(Threshold/Ratio/Attack/Release/Gain/Mix) — только через UI**.

### 10.3 Как менять компрессор программно

Координаты на панели эффектов (Live-режим, DPI 1.75):

| параметр | dial (логические) | физические |
|---|---|---|
| Threshold | `[376]` (756,1302) | (432,744) |
| Ratio | `[397]` (958,1384) | (548,791) |
| Attack | `[396]` (1020,1262) | (583,721) |
| Release | `[403]` (1086,1384) | (621,791) |
| Gain | `[381]` (756,1464) | (432,837) |
| Mix | `[331]`? | уточнить |

**Метод:** `SetCursorPos(px/1.75, py/1.75)` → mouse DOWN → движение по Y
→ UP. Каждые ~4 px движения дают ~1 единицу значения.

**Ограничение:** точное значение задать трудно — dial не поддерживает
`RangeValuePattern`, а двойной клик открывает не то поле. Погрешность
±3–5 единиц. Для точности нужен диалог EQ/компрессора, который пока
не разобран.
