# Dev-сервер (исторический)

Этот каталог — **не продакшн-код**. Сайт его не использует и не
загружает. Он оставлен как история разработки и справочник по
реверс-инжинирингу.

## Что здесь

| Файл | Что делает |
|---|---|
| `server.js` | HTTP + WebSocket с 50 маршрутами `/api/*` |
| `audio-params.js` | параметры аудио (частота, буфер) |
| `comp-control.js` | управление компрессором через API |
| `controls-service.js` | абстракция над контролами |
| `duck-loopback-hid.js` | ducking и loopback |
| `eq-control.js` | управление EQ через API |
| `eq-mixer.js` | матрица EQ-микшера |
| `eq-scales.js` | шкалы EQ |
| `modes.js` | определение режима карты |
| `settings-service.js` | сохранение настроек |
| `snapshots.js` | снимки состояния на диск |
| `state-store.js` | хранилище состояния |
| `ui-control.js` | управление окном MCC через UI Automation |
| `workspace.js` | рабочее пространство |
| `workspace-service.js` | сервис рабочих пространств |

## Почему уехало из `src/`

Изначально архитектура была «сервер управляет картой через `node-hid`,
браузер — тонкий клиент». От этой схемы отказались: карта управляется
**напрямую из браузера через WebHID**, сервер отдаёт только статику.

Причина — в требованиях к хостингу. Вариант с сервером означал бы:

- нужен сервер с USB-доступом к карте у каждого пользователя;
- у пользователя должна быть установлена M62 на этом сервере;
- нельзя захостить на GitHub Pages / Cloudflare Pages;
- каждый пользователь влияет на общий процесс.

WebHID решает всё это: карта подключена к машине самого пользователя,
браузер общается с ней напрямую, сервер не знает о ней ничего.

Проверить, что клиент действительно не ходит на сервер:

```bash
# ни одного fetch/XMLHttpRequest/WebSocket в клиенте
grep -rn "fetch(\|XMLHttpRequest\|new WebSocket" web/
```

## Почему не удалено совсем

Каталог `research/` — это документация по реверсу: здесь лежит то,
что помогло понять протокол. Dev-сервер показывает, как состояние
карты читалось и писалось через `node-hid`, и какие API
предполагались. Для будущих задач (например, настольное приложение
или CLI) это готовый справочник.

## Как запустить

Нужна зависимость `ws`, которую мы убрали из основного
`package.json` — она нужна только этому серверу:

```bash
npm install ws
node research/dev-server/server.js
# HTTP  http://127.0.0.1:8787
# WS    ws://127.0.0.1:8787/ws
```

Сервер попытается открыть карту через `node-hid`. На машине без M62
он запустится, но `/api/health` покажет `connected: false`.

## Чего здесь нет

- **Проверок в CI.** Каталог исключён из линтера (`research/**`) и
  проверки типов (`jsconfig.json`). Код может не соответствовать
  текущим правилам.
- **Тестов.** `test-robustness.js` проверял именно этот сервер и
  убран из `npm run test:server` — он тестировал API, которого в
  продакшене нет.
- **Гарантий актуальности.** Импорты поправлены на момент переноса
  (`check-devserver-imports.js`), но дальше каталог не сопровождается.

Если понадобится вернуть его в активную разработку — сначала
разобраться, зачем: продакшн-путь сейчас не предполагает серверного
API вообще.
